# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**csl-sqlite** is a distribution repository for the SQLite databases of the Cologne Digital Sanskrit Lexicons (CDSL). It provides the latest compiled dictionaries as GitHub Releases assets, allowing users and downstream scripts to download current data without cloning the full pipeline.

**Do not `git pull` this repository.** Each Release publishes ~50 zipped SQLite files totalling ~250 MB as release assets (not in the git tree). A plain pull won't fetch them, but the discouragement is to remind users that the data lives in Releases, not in the tree.

## Usage

To get the latest SQLite files:
1. Go to the [latest release](https://github.com/sanskrit-lexicon/csl-sqlite/releases/latest)
2. Download the `<short>.zip` for the dictionary you need; each zip contains `<short>.sqlite`

Or use the GitHub CLI:
```bash
gh release download --repo sanskrit-lexicon/csl-sqlite --pattern "<short>.zip"
unzip <short>.zip      # extracts <short>.sqlite
```

## Architecture

SQLite files are generated by csl-pywork (template at
[`v02/makotemplates/pywork/sqlite/sqlite.py`](https://github.com/sanskrit-lexicon/csl-pywork/blob/master/v02/makotemplates/pywork/sqlite/sqlite.py))
from the canonical source text in csl-orig.

Each `<short>.sqlite` contains **one table named after the dictionary's short name**:

```sql
CREATE TABLE <short> (
  key  VARCHAR(100) NOT NULL,     -- headword (SLP1)
  lnum DECIMAL(10,2) UNIQUE,      -- entry number; non-UNIQUE for abch, acph, acsj
  data TEXT NOT NULL              -- XML-wrapped entry content
);
CREATE INDEX datum ON <short>(key);
```

The release cycle: when csl-orig is corrected and csl-pywork reruns, updated SQLite
files are uploaded as a new GitHub Release here. See [ARCHITECTURE.md](ARCHITECTURE.md)
for the full pipeline and the auxiliary `_lslinks` / `hwnorm1c` / `keydoc_glob1` files.

## Dependencies

This repo has no scripts — it is a distribution channel only. The generation pipeline lives in `csl-pywork`.
