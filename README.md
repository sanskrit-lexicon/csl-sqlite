# csl-sqlite

_Created: 14-06-2026 · Last updated: 11-07-2026_

**Distribution store for the compiled SQLite databases of the Cologne Digital
Sanskrit Dictionaries (CDSL).** This repository holds almost no source — it is a
delivery channel that ships the latest per-dictionary SQLite databases (packaged
as `.zip`) so users and downstream tools can fetch current data without cloning
or rebuilding the full CDSL pipeline.

Part of the [sanskrit-lexicon](https://github.com/sanskrit-lexicon) project.

## What is published here

Each Cologne dictionary is compiled to a single `<dict>.sqlite` and published
zipped as `<dict>.zip`. The current set covers 40+ dictionaries — including
`mw` (Monier-Williams), `pw`/`pwg` (Petersburg), `ap`/`ap90` (Apte), `gra`,
`bhs`, `md`, `sch`, `vcp`, `skd`, and many more — alongside:

- `<dict>_lslinks.sqlite.zip` — per-dictionary link-resolution databases
  (`<ls>` citation → scan-page links), e.g. `mw_lslinks.sqlite.zip`.
- Shared helper databases such as `hwnorm1c.sqlite.zip` (headword
  normalization) and `keydoc_glob1.sqlite.zip`.

## Two delivery channels

Both channels carry the same `.zip` assets and are refreshed together, roughly
weekly.

1. **GitHub Releases** — one dated release per rebuild, tagged
   `Release YYYY-MM-DD-HH-MM-SS`. Grab the latest at
   [releases/latest](https://github.com/sanskrit-lexicon/csl-sqlite/releases/latest).

2. **GitHub Pages** (the [`gh-pages`](https://github.com/sanskrit-lexicon/csl-sqlite/tree/gh-pages)
   branch) — the same zips served over HTTPS at
   [sanskrit-lexicon.github.io/csl-sqlite/](https://sanskrit-lexicon.github.io/csl-sqlite/),
   with an `index.html` listing. This is the runtime supply chain fetched by
   browser/app clients (e.g. [csl-app](https://github.com/sanskrit-lexicon/csl-app))
   that need same-origin, CORS-friendly downloads.

## Usage

Download a single dictionary from the latest release with the GitHub CLI:

```bash
gh release download --repo sanskrit-lexicon/csl-sqlite --pattern "mw.zip"
unzip mw.zip        # -> mw.sqlite
```

Or fetch the same asset over HTTPS from GitHub Pages:

```bash
curl -O https://sanskrit-lexicon.github.io/csl-sqlite/mw.zip
```

**Do not `git clone`/`git pull` for the data.** The databases are large binaries
delivered as Release/Pages assets (not committed to `main`, and not stored via
Git LFS — there is no `.gitattributes`). Cloning the branches would not give you
the current SQLite files; use the release or Pages URL instead.

## How the data is produced

The SQLite databases are generated by the CDSL build pipeline from the digitized
dictionary source in
[csl-orig](https://github.com/sanskrit-lexicon/csl-orig). When source text is
corrected and the pipeline reruns, a fresh dated release (and a `gh-pages`
refresh) is published here. Pipeline and tooling context lives in the
[Cologne tooling runbook](https://github.com/sanskrit-lexicon/csl-observatory/blob/main/runbook/cologne-tooling-runbook.md).

## Consumers

Known downstream users of these databases:

- [csl-app](https://github.com/sanskrit-lexicon/csl-app) — fetches the
  `gh-pages` zips as its runtime dictionary store.
- [csl-apidev](https://github.com/sanskrit-lexicon/csl-apidev) — the C-SALT API
  development repo tests against `mw.sqlite` fetched from a release.
- [kosha](https://github.com/gasyoun/kosha) — the Sanskrit data hub consumes
  csl-sqlite releases as an upstream source.
